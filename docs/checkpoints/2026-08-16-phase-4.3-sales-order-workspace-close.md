## 1. Scope & Resolved CTO Blockers

### Blocker 1: Sales Order Brand Snapshot Integrity
- **Inheritance at Conversion:** Approved Quotation's `documentBrandSnapshot` is copied to Sales Order upon conversion in `buildApprovedQuotationSalesOrderDraft`.
- **Immutability & Safety:** `SalesOrder` domain entity stores `_documentBrandSnapshot` with `structuredClone` semantics on getter and constructor, preventing reference leakage.
- **Persistence & Mapping:** Updated `PrismaSalesOrderMapper` using `parseCompanyDocumentBrandSnapshot` for persistence JSON -> domain, and `PrismaSalesOrderRepository` using `Prisma.InputJsonValue` for domain -> database persistence. Snapshot is immutable across lifecycle operations (`confirm`, `cancel`).
- **PDF Generation Fallback:** `GenerateSalesOrderDocumentUseCase` uses persisted `salesOrder.documentBrandSnapshot` first, falling back to live Company branding only for legacy Sales Orders with a null snapshot.

### Blocker 2 & 5: Audit History Preservation & Renderer Logic
- **Confirmation Preservation Post-Cancellation:** Confirmation audit details in `SalesOrderDocumentSnapshot` now depend strictly on `salesOrder.confirmedAt` existing, rather than requiring current status to be `CONFIRMED`.
- **Status-Agnostic Timeline:** `PdfKitSalesOrderDocumentRenderer` now renders timeline history based on actual immutable audit entries. A `CANCELLED` order previously `CONFIRMED` shows source quotation approval, creation, confirmation, and cancellation with reason. A directly cancelled `DRAFT` order shows approval, creation, and cancellation without fake confirmation.

### Blocker 3: Sales Order Creation Audit Timestamp
- **Audit Date Accuracy:** Added `createdAt` to `SalesOrderDocumentSnapshot`. `GenerateSalesOrderDocumentUseCase` supplies `salesOrder.createdAt` (or `orderDate` fallback for transient entities).
- **Renderer Display:** `PdfKitSalesOrderDocumentRenderer` formats and displays `createdAt` for creation audit instead of commercial `orderDate`. Regression tests verify `orderDate != createdAt`.

### Blocker 4: Multi-Page PDF Pagination
- **Vertical Overflow Detection:** `PdfKitSalesOrderDocumentRenderer` calculates available vertical space (`pageMaxY`) before drawing table headers, line items, totals cards, and audit boxes.
- **Page Breaking & State Restoration:** Automatically creates a new A4 page before row or block overflow, re-applies letterhead/cover if configured, restores font and RTL text direction (`Cairo-Variable.ttf`, `configureProposalTextDirection`), respects margins and safe areas, and re-renders table headers on subsequent pages.
- **Footer & Page Numbers:** Decorated page numbers and footers work seamlessly across single-page and multi-page generated documents.

### Blocker 6: Sales Order Activity Tenant Safety
- **Tenant Scope Enforcement:** Parent Sales Order is verified via `(companyId, salesOrderId)`. Activity repository listings and saves remain strictly tenant-scoped.
- **Server Authority & Spoof Resistance:** `POST /api/sales-orders/[salesOrderId]/activities` derives actor identity, role, and timestamp strictly from server authentication and company context, ignoring body spoofing attempts. Cross-tenant or missing order lookups return 404 without calling activity save. Max body length of 2000 chars is enforced.

### Blocker 7: Input Validation / API Hardening
- **Lifecycle Expected Status Parsers:** Explicit parsers exist for confirm route (`expectedStatus === "DRAFT"`) and cancel route (`expectedStatus === "DRAFT" | "CONFIRMED"`).
- **Malformed Request Protection:** Handles malformed JSON and invalid request bodies cleanly with 400 Bad Request responses.

### Blocker 8: UTF-8 Inspection
- Verified that source and test files decode cleanly as UTF-8. Powershell decoding issues observed during earlier output were confirmed to be terminal display artifacts.
