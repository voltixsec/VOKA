## A. Exact automated tests to run

### A.0 Database rule — how to run this validation

- **Offline / focused validation (no live DB):** `npm ci` and `npx prisma generate` (generation reads the Prisma schema only — it does **not** connect to any database), then `npm run typecheck` and the offline test sets in §A.1–§A.2 (every listed suite mocks `@/lib/prisma` and/or the `withCompanyAuth` wrapper — no PostgreSQL needed). This sandbox has no `node_modules` and no `.env`, so even the offline sets are **not yet executed here**; they are queued for the next runnable environment.
- **DB-backed / full-suite validation: `PENDING`.** Any test or suite that exercises the real Prisma client / a live repository (e.g. `CustomerCodeAllocator.persistence.test.ts`, which is gated by `VOKA_RUN_DB_TESTS=1`, DB-integrity suites under `features/universal-library/**`, and the full `npm test -- --run`) requires PostgreSQL. It will be run **only** against the **dedicated disposable test database** that will be provided later — never the office/shared database. The reference command shape below is the CI definition (`.github/workflows/quality.yml`), whose Postgres 16 is an ephemeral service container created and destroyed per run; it is the only place `migrate deploy` is acceptable, and it never points at a shared database:

```bash
# CI-ONLY (ephemeral disposable Postgres service container — never a shared/office DB)
npm ci
npx prisma generate
npx prisma migrate deploy          # disposable CI Postgres only
npm run typecheck
VOKA_RUN_DB_TESTS=1 npm test -- --run
```
